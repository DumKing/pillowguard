# 当前范围：持续坐起提醒

当前版本仅启用持续坐起提醒。站起不单独区分，开始坐起早期提示、床沿、离床和疑似跌倒规则已暂停，界面入口已移除。旧配置即使保留相关开关，也不能触发这些类型的通知。历史记录保留。

现有肩髋模型判断的是画面中的躯干竖直，因此不能保证把坐着和站着分开；站姿仍可能被归入坐起。高位斜俯视或盖被子时，可使用固定机位卧床/坐起辅助校准。不能把暂时无法识别人直接当成离床或跌倒。

普通规则先确认躺卧 2 秒，再持续坐起达到所选时长。可选“无法识别后检测到坐起，也发送告警”；多人暂停，监测时段、告警间隔、第二人阈值和多渠道通知继续生效。异常提醒保留独立开关，可按实际需求开启或关闭。

默认无需人工确认，首次告警直接触发。重复提醒和超时升级仍可独立配置，默认关闭；按次数上限与状态恢复处理。确认重新躺卧、多人进入、停止监测或更换来源后结束当前事件的后续通知。配置和告警记录会永久保存。

人工确认是可选能力，默认关闭。日后如需手机确认，可增加通知里的轻量确认页面，使用有时效的单次令牌，用户打开后点击“我已接手”；仅预览链接不应视为确认。该手机确认页尚未实现，目前不依赖它。

## 升级连续播报

升级现在使用已启用的小爱音箱渠道，不再保留单独的升级通知渠道。首次告警和普通重复提醒仍发送给全部已启用渠道；告警持续达到升级时间后，每个启用的音箱连续播放设定次数（默认 3 次，最多 10 次）。默认升级时间 120 秒，播放后间隔 3 秒，可在监测规则中永久保存。

音箱接口只返回请求接受状态。软件按文案长度估算播放时长，再加上设置的间隔，不能保证准确的播放完成时间。每次请求包含次数标记，避免连续相同文本被设备忽略。多个音箱同时发送，本轮中任一请求失败或超时即停止后续连播，不重试结果不明的请求。

重新确认躺卧、多人进入、停止监测、离开监测时段、关闭升级或人工确认（如果启用）会取消尚未发送的次数；已经交给音箱的播放不能撤回。演示模式同样执行这些规则，视频回放不发送通知。升级期间暂停普通重复提醒调度，结束后仍受原有普通提醒次数上限约束。重启不会补发已触发过的升级连播。
